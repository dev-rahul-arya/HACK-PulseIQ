# PulseIQ Health Intelligence

PulseIQ is a personal health co-pilot that aggregates your health data to provide actionable insights, weekly stories, and gentle nudges. It uses AI (Claude) to analyze cross-signal patterns in your sleep, resting heart rate, HRV, and activity to help you understand your health better.

## Features

- **Daily Insights:** AI-generated personalized observations based on your last 24 hours of health data.
- **Weekly Stories:** A reflective summary of your week's health trends.
- **Timeline & Metrics:** Visualize your health data over time with interactive charts.
- **Privacy-First:** Utilizes local storage (IndexedDB via Dexie) for fast, secure on-device data management.
- **PWA Support:** Installable as a Progressive Web App for a native-like experience.

## Tech Stack

- **Frontend:** React 19, Vite, Tailwind CSS, Framer Motion
- **State Management:** Zustand
- **Database:** Dexie (IndexedDB)
- **Charts:** Recharts
- **AI Integration:** Anthropic Claude API (proxied via Vite for local dev)

## Getting Started

### Prerequisites
- Node.js (v18+)
- npm or pnpm

### Installation

1. Clone the repository and navigate to the `app` directory.
2. Install dependencies:
   ```bash
   npm install
   ```
3. Set up environment variables:
   Copy `.env.example` to `.env.local` and add your Anthropic API key.
   ```bash
   cp .env.example .env.local
   ```
4. Start the development server:
   ```bash
   npm run dev
   ```
5. append `?bypass=install` to the URL — useful for browser preview/testing on a phone without actually installing.

## How the data and the score work

Because the app is offline-first and there is no real Apple Health / Google Fit
hookup yet, everything you see in the demo comes from a deterministic synthetic
dataset and a simple, transparent scoring function. Both are designed so a
reviewer can read the source and reproduce every number on screen.

### Sample dataset (`src/data/sampleData.js`)

When you tap **Profile → Connected Apps → Sync Apple Health / Google Health
Connect**, the app does *not* hit any real API. Instead it generates **30 days
of synthetic-but-realistic records** and writes them to IndexedDB.

- Generated by a seeded PRNG (`mulberry32(20260426)`) so the same demo is
  reproducible across reloads and devices.
- `dayIndex 0` = oldest day, `dayIndex 29` = today.
- Per day it writes:
  - `sleep` — one record/night with hours plus deep / REM / light / awake breakdown
  - `restingHR` — one morning reading (bpm)
  - `hrv` — one morning reading (rMSSD-style ms)
  - `heartRate` — twelve daytime samples (bpm)
  - `steps` — one daily total
  - `activeMinutes` — derived from steps
- Plus a small set of seeded manual logs (mood, symptoms, BP, weight) over the
  last two weeks so the timeline isn't empty.

The generator deliberately bakes **two cross-signal patterns** so the AI has
something to find:

| Window               | What happens                                         | Why it matters                                 |
| -------------------- | ---------------------------------------------------- | ---------------------------------------------- |
| Days 12–16 (~2 wks ago) | Sleep drops to ~5h, resting HR +6 bpm, HRV −14 ms | Drives the "rough week" narrative in the weekly story |
| Days 17–19           | Sleep recovers (+0.5h), HR / HRV linger high         | Demonstrates that recovery is gradual, not instant |
| Days 14–18           | Steps drop ~1500/day                                 | Shows activity dip as a downstream effect of the sleep loss |
| Days 25–28 (recent)  | Sleep ~6h, resting HR +4 bpm, HRV −8 ms              | Gives **today's** circadian risk score something real to surface |

If you want to reset and re-generate (e.g., after pulling new sample-data
changes), use **Profile → Data & privacy → Clear local data**, then re-sync.

### Circadian Risk Score (`src/utils/calculations.js`)

The big number on Today is a **weighted composite of four contributors** —
intentionally simple and explainable, not a black-box ML score. Each
contributor is normalised to `[0, 1]`, weighted, and the result is rounded
to `0–100`.

| Contributor          | Weight | What we measure                                                                                  | Saturates at        |
| -------------------- | ------ | ------------------------------------------------------------------------------------------------ | ------------------- |
| **Sleep debt**       | 35%    | Sum of `(8h − sleep_hours)` over the last 3 nights (clipped to ≥ 0)                              | 9h total debt       |
| **Resting HR drift** | 25%    | `mean(last 3 days) − mean(prior days)` from a 14-day series, in bpm                              | +10 bpm above baseline |
| **HRV decline**      | 25%    | `mean(prior days) − mean(last 3 days)` from a 14-day series, in ms (lower HRV = worse)           | −15 ms below baseline |
| **Activity inconsistency** | 15% | Coefficient of variation (`stdev / mean`) of the last 7 days' step count                      | CV of 0.6           |

Bands (set in `riskBand()`):

- `0–24` Low (green)
- `25–49` Moderate (yellow)
- `50–74` Elevated (orange)
- `75+` High (red)

The contributor breakdown bars on Today show each contributor's individual
0–100 score so the user (and a clinician) can see *which* signal is driving
the composite — not a mystery number.

### How Claude is called

All AI calls go through a tiny POST to `/api/ai`, which in dev is a
middleware in `vite.config.js` that proxies to
`https://api.anthropic.com/v1/messages` server-side. **The API key never reaches
the browser.** For a production deploy you would move this proxy to a
serverless function (Netlify / Vercel / Cloudflare Workers).

Three call sites, all in `src/services/ai.js`:

1. **`getDailyInsight(payload)`** — once per device per day. Sends a compact
   summary (sleep, resting HR + 14-day baseline, HRV + baseline, steps,
   active minutes, mood, symptoms, 7-day averages, and the user's focus
   goals). Asks for JSON: `{ insight, nudge, confidence }`. Cached in Dexie
   keyed by date so we never re-bill on a refresh.
2. **`getWeeklyStory(payload)`** — on demand from the Insights tab. Sends
   7-day arrays (sleep / resting HR / HRV / steps + recent manual logs +
   focus goals). Asks for JSON: `{ story, keyTakeaway }`.
3. **`askFollowUp({ insightSummary, contextSummary, history, question })`**
   — the chat-style follow-up under each insight. Sends the original insight
   + a flattened snapshot of the data the insight was based on + the running
   conversation. Each insight stores its own `conversation` array on the
   Dexie row so threads survive reloads.

Every system prompt explicitly instructs Claude to **never diagnose, never
prescribe**, to cite the specific signal driving each claim, and to suggest
talking to a clinician when language gets risky. We use
`claude-haiku-4-5-20251001` for cost / latency on the hackathon plan; swap the
`MODEL` constant in `services/ai.js` to upgrade.

If Claude is unreachable (offline, missing key, API error) the daily and
weekly call sites fall back to a deterministic mock insight so the demo never
breaks visually — the card just shows a small "fallback" tag.

### Data privacy

- Health metrics, manual logs, and AI insights live in IndexedDB on the device
  via Dexie (`pulseiq` database, see `src/db/db.js`).
- The Supabase backend stores **only** auth + a small `user_profiles` row
  (display name, age, height, weight, focus goals). No health metrics ever
  leave the device.
- When you call Claude, only the aggregated payload above is sent — no raw
  per-minute heart-rate samples, no symptom free-text beyond the manual
  category, no name or identifiers.
- **Profile → Data & privacy → Clear local data** wipes every Dexie table.
  **Delete account** also removes the Supabase row.
